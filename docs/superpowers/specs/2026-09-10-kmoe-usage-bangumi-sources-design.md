# Kmoe 用量与 Bangumi 订阅源设计

日期：2026-09-10
状态：实现中

## 目标

1. 从 Kmoe 账号页读取并展示免费/VIP 下载额度。
2. 建立可扩展订阅源模型，首个适配器读取 Bangumi 用户的想看、看过、在看、搁置和抛弃收藏，并支持按周期自动同步。

## Kmoe 用量

- 用量解析留在 `src/kmoe_subscriptions/kmoe/`。
- 仅解析账号页明确提供的免费/VIP 总额、已用量和重置日；字段缺失时保持未知，禁止推断成无限额度。
- 登录成功后保存一次额度快照；管理员可从设置页手动刷新。
- 数据库不保存 Kmoe 密码、原始账号页或 Cookie 明文。
- 概览显示免费与 VIP 的合计剩余额度，设置页显示分层详情。

## 订阅源

建立通用的 `SubscriptionSource` 与 `SubscriptionSourceItem`：

- `SubscriptionSource` 保存来源类型、名称、非敏感配置、启用状态、同步周期和最近同步结果。
- `SubscriptionSourceItem` 保存规范化外部条目、来源状态、标题、封面、外部链接和用于 Kmoe 搜索的关键词。
- 首个来源类型是 `bangumi`，配置包含用户名与需要读取的收藏状态。
- 公开收藏只需用户名；可选 `KMOE_BANGUMI_ACCESS_TOKEN` 用于读取调用者有权访问的私密收藏。
- 同步是单向读取，不反写 Bangumi。
- 来源条目不会自动创建 Kmoe 订阅。Bangumi 与 Kmoe 没有稳定共享 ID，模糊搜索可能匹配错误，因此必须由管理员在 Kmoe 结果中确认后订阅。
- 删除来源只删除来源快照，不删除已存在的 Kmoe 订阅或下载文件。
- 每个来源可配置同步周期（小时），后台定时器检查到期来源并自动同步。

订阅源管理位于独立的“订阅源”导航页，支持添加用户名、选择状态、手动同步、编辑同步周期和删除。

模型与 API 保留后续接入 RSS/Atom 或其他目录源的边界，但在明确条目身份与下载语义前不接受任意 URL 作为下载源。

## 安全与失败处理

- Bangumi Access Token 仅通过环境变量传入，不入数据库、API 响应或日志。
- 用户名限制为安全路径字符；所有 Bangumi URL 由适配层固定构造。
- Bangumi 失败映射为结构化 `bangumi_unavailable` 或 `bangumi_user_not_found`，保留旧快照。
- Kmoe 用量解析失败不影响有效会话，只显示“额度未知”。
