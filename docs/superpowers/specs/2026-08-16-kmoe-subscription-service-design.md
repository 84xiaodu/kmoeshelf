# Kmoe 自动订阅与下载服务设计

日期：2026-08-16  
状态：已确认设计，等待书面规格复核

## 1. 背景与目标

本项目构建一个面向 NAS 或 Linux 服务器的常驻 Web 服务，对接 Kmoe 漫画站点，实现漫画搜索、订阅、定时追新、自动下载和任务状态管理。

首版服务采用 Docker Compose 部署，服务单个管理员与单个 Kmoe 账号，仅供局域网访问。管理员可在 Web 界面完成日常操作，无需直接运行命令行工具。

参考项目：

- [holdjun/kmoe](https://github.com/holdjun/kmoe)：异步客户端、镜像故障转移、搜索、页面解析、本地库与更新流程。
- [chrisis58/kmoe-manga-downloader](https://github.com/chrisis58/kmoe-manga-downloader)：并发下载、断点续传、重试与自动化经验。

系统不通过子进程包装参考 CLI，也不整体 Fork 其中任一项目。系统拥有独立的订阅领域模型、数据库、任务队列和 Web API，并通过可替换的 Kmoe 适配层隔离站点细节。若选择性移植参考项目的 MIT 许可代码，必须保留对应版权和许可证声明，并在发布物中提供第三方许可文件。

## 2. 首版范围

### 2.1 包含

- 管理员登录与会话管理。
- 在 Web 中登录一个 Kmoe 账号。
- 按关键词搜索漫画，支持站点可提供的语言筛选和分页。
- 查看漫画详情、封面、作者、简介和远端内容列表。
- 创建、编辑、启用、暂停和删除订阅。
- 每部漫画分别选择追踪单行本、番外、连载话中的一种或多种。
- 每部漫画选择 EPUB 或 MOBI 下载格式。
- 创建订阅时选择“下载全部已有内容”或“仅从当前基线开始追新”。
- 全局定时检查，默认每 6 小时执行，可在 Web 中调整。
- 发现新增内容后自动创建下载任务。
- 查看队列、实时进度、速度、状态、失败原因和最终文件路径。
- 取消等待中或下载中的任务，手动重试失败任务。
- 配置下载并发数、重试次数和首选镜像。
- Docker Compose 部署与持久卷。

### 2.2 不包含

- 多管理员或多租户。
- 多 Kmoe 账号、账号池或配额故障转移。
- 公网暴露所需的内建 HTTPS、OAuth、统一身份认证或高级限速策略。
- Komga、Kavita、Webhook 或下载完成回调。
- 内建漫画阅读器。
- 移动端原生应用。
- CLI 管理客户端。

## 3. 成功标准

- 管理员能在 Web 中完成 Kmoe 登录、搜索漫画并创建订阅。
- 定时检查能基于稳定的远端内容标识发现新增单行本、番外或连载话。
- 同一远端内容和格式不会因重复检查产生多个有效下载任务。
- 下载成功后文件位于可预测目录，数据库状态与磁盘文件一致。
- 网络中断或服务重启不会产生被误认为完成的文件；可恢复任务继续执行，不可恢复任务安全重试。
- 单部漫画检查失败或单个下载失败不会阻塞其他订阅与任务。
- Kmoe 密码不落盘，日志不泄漏密码、Cookie 或签名下载地址。
- Docker 容器重建后，只要持久卷保留，订阅、任务记录、加密 Session 和已下载文件均不丢失。

## 4. 总体架构

首版采用一个应用容器，内部保持模块化分层：

1. React Web 界面负责管理员操作和状态展示。
2. FastAPI 提供同源 REST API、管理员认证、业务规则和静态资源。
3. APScheduler 触发全局订阅检查。
4. 内建异步任务工作器处理检查任务与下载任务。
5. Kmoe 适配层封装登录、搜索、详情解析、镜像选择和下载传输。
6. SQLite 保存业务状态；下载目录保存 EPUB、MOBI 和临时文件。

首版不引入 Redis、Celery 或独立 Worker 容器。SQLite 是任务状态的唯一事实来源，进程内队列只用于唤醒工作器。服务启动时从数据库恢复仍需处理的任务。

### 4.1 技术栈

- Python 3.12
- FastAPI
- SQLAlchemy 2 与 Alembic
- APScheduler
- HTTPX 与 AnyIO
- SQLite WAL
- React、TypeScript 与 Vite
- SSE 实时状态推送
- Pytest 与 Playwright
- Docker 与 Docker Compose

前端构建产物由 FastAPI 提供，浏览器与 API 保持同源，降低部署复杂度。普通查询和命令使用 REST；任务进度及状态变化使用单向 SSE，不需要 WebSocket。

## 5. 模块边界

### 5.1 Web 前端

只通过公开 API 操作系统，不了解 Kmoe HTML、Cookie 格式或下载协议。前端展示服务端返回的结构化错误，不从日志文本推断业务状态。

### 5.2 API 与应用服务

负责参数校验、管理员授权、事务边界和业务规则。API 不直接请求 Kmoe，也不直接写下载文件，而是调用应用服务或创建持久化任务。

### 5.3 调度器

按全局间隔创建订阅检查批次。调度器本身不抓取站点。若上一次批次仍在执行，不并发创建相同批次；管理员触发“立即检查”也经过相同的互斥与去重规则。

### 5.4 任务工作器

从数据库领取任务，维护等待、运行、完成、失败和取消状态。任务领取必须是原子的，确保同一任务不会被两个协程同时执行。工作器分别限制远端检查并发和文件下载并发。

### 5.5 Kmoe 适配层

暴露稳定接口：

- 登录并返回 Session/Cookie 与账号状态。
- 验证现有 Session。
- 搜索漫画。
- 获取漫画详情和标准化远端内容列表。
- 获取下载信息并传输文件。

适配层内部处理镜像故障转移、请求节流、页面解析和站点错误映射。其他模块不得依赖站点 URL 形态、HTML 选择器或格式编号。

### 5.6 存储层

数据库操作通过 Repository 接口集中实现。文件存储模块负责安全文件名、目录布局、临时文件、原子改名与磁盘校验，避免业务层拼接任意路径。

## 6. 核心数据模型

### 6.1 Admin

保存唯一管理员的密码哈希、密码更新时间和会话失效版本。数据库从不保存管理员明文密码。

### 6.2 KmoeCredential

保存 Kmoe 用户标识、加密后的 Session/Cookie、登录状态、配额摘要和最近验证时间。Kmoe 密码不属于该模型。

### 6.3 Comic

保存站点漫画 ID、规范详情 URL、标题、作者、语言、封面、简介和最近同步时间。站点漫画 ID 是稳定业务标识，不以标题作为唯一键。

### 6.4 Subscription

每部漫画最多存在一个订阅，保存：

- 启用状态。
- 追踪内容类型集合：`volume`、`extra`、`serial`。
- 下载格式：`epub` 或 `mobi`。
- 初始化策略：`backfill` 或 `future_only`。
- 上次成功检查时间、上次尝试时间、下次检查时间和最近错误。

### 6.5 RemoteItem

保存某漫画的远端卷、番外或连载话快照，包括远端内容 ID、类型、名称、排序信息、大小、页数、首次发现时间和最近确认时间。唯一键为站点漫画 ID 与远端内容 ID；如站点不同类型可能复用 ID，则将内容类型加入唯一键。

### 6.6 DownloadTask

保存远端内容、下载格式、状态、优先级、尝试次数、进度字节、总字节、速度、临时路径、最终路径、错误类型、错误摘要和时间戳。

同一远端内容与下载格式只能有一个有效任务。数据库唯一约束而非仅靠应用判断来保证幂等性。已完成文件丢失时可将原任务标记为文件缺失，再显式创建补偿重试，而不是悄悄重复下载。

### 6.7 AppSetting 与 ActivityEvent

`AppSetting` 保存检查间隔、并发数、重试次数和首选镜像。`ActivityEvent` 保存适合在仪表盘展示的结构化活动，例如检查完成、新内容发现、下载完成和认证失效，不保存敏感数据。

## 7. 关键流程

### 7.1 首次配置

1. 服务发现尚无管理员，显示初始化页。
2. 用户创建管理员密码。
3. 用户配置 Kmoe 邮箱和密码并提交登录。
4. 服务仅在内存中使用密码完成登录。
5. 登录成功后，加密保存 Session/Cookie 并清除密码引用。
6. 登录失败时不保存无效凭证。

管理员初始化只能在系统尚无管理员时执行，并通过数据库事务保证只能成功一次。

### 7.2 创建订阅

1. 用户搜索并进入漫画详情。
2. 服务完整获取详情和当前远端内容列表。
3. 用户选择内容类型、格式和初始化策略。
4. 服务在单个事务中创建或更新 Comic、RemoteItem 与 Subscription。
5. `backfill` 为所有符合筛选条件的现有内容创建下载任务。
6. `future_only` 将当前内容保存为已知基线，不创建下载任务。

只有详情与内容列表成功解析后才能提交订阅，避免把站点异常返回的空列表记录为有效基线。

### 7.3 定时追新

1. 调度器创建检查批次。
2. 工作器逐个读取启用的订阅，并受检查并发限制。
3. 适配层获取最新详情与内容列表。
4. 服务按远端内容 ID 和类型与数据库快照比较。
5. 对符合订阅筛选条件的新增内容创建 DownloadTask。
6. 在同一事务中更新快照和订阅的成功检查时间。
7. 检查失败时保留旧基线，只记录尝试时间和错误。

空列表只有在响应结构通过有效性校验且站点明确表示无内容时才可接受。解析器无法确认页面结构时必须报“站点结构变化”，不能把结果当作内容被删除。

### 7.4 下载

1. 工作器原子领取等待任务并标记运行。
2. 适配层获取短期有效的真实下载地址。
3. 文件写入目标目录中的 `.part` 临时文件。
4. 可用时根据服务器能力进行续传；若服务器不支持 Range，则删除不可信临时段后重新下载。
5. 持续更新数据库进度，并通过 SSE 向页面推送节流后的事件。
6. 下载结束后校验响应长度、非空文件和期望扩展名。
7. 使用原子改名移动到最终文件名，再将任务标记完成。

数据库绝不在最终文件成功落盘前标记任务完成。

### 7.5 重启恢复

服务启动时将遗留的运行中任务重新分类：存在可续传临时文件的任务回到等待状态；无法安全恢复的任务清理无效临时状态后回到等待状态。已请求取消的任务保持取消状态。恢复过程必须幂等。

## 8. 文件布局

容器路径：

- `/data/app.db`：SQLite 数据库。
- `/data/backups/`：迁移或维护时生成的数据库备份。
- `/downloads/`：下载根目录。

建议文件布局：

```text
/downloads/
  <漫画标题> [<漫画ID>]/
    volumes/
    extras/
    serials/
```

文件名包含经过清理的内容名称、远端内容 ID 和扩展名，远端 ID 防止同名卷冲突。路径清理必须阻止绝对路径、`..`、控制字符和跨平台非法字符。标题变更不自动移动已完成文件，避免大规模重命名；后续下载继续使用订阅首次建立时确定的库目录名。

## 9. Web 页面

### 9.1 初始化与登录

首次启动创建管理员；之后显示管理员登录页。页面明确区分“管理员会话”和“Kmoe 登录状态”。

### 9.2 仪表盘

显示订阅总数与异常数、下载中和等待任务数、下次检查时间、Kmoe 会话状态、最近活动，并提供“立即检查全部订阅”。

### 9.3 搜索与详情

支持关键词、语言筛选和分页。结果展示封面、标题、作者和漫画 ID。详情页展示远端内容分组，并提供创建或编辑订阅入口。

### 9.4 我的订阅

展示启用状态、追踪类型、格式、最近与下次检查、未完成任务和最近错误。支持启停、编辑、删除和单独立即检查。删除订阅不删除已完成文件；是否取消未开始任务需要用户明确选择。

### 9.5 下载任务

按状态和漫画筛选，展示进度、速度、尝试次数、错误与文件路径。等待或运行任务可取消；失败任务可重试。已完成记录默认保留，不提供首版批量物理删除功能。

### 9.6 设置

管理 Kmoe 登录、全局检查间隔、下载并发、重试次数、首选镜像和管理员密码。危险或影响正在运行任务的配置变更需要明确提示。

响应式布局保证手机浏览器可完成主要操作，但首版不追求原生移动端体验。

## 10. 安全设计

- 管理员密码使用 Argon2id 哈希。
- 管理员会话使用随机不透明令牌或签名会话，Cookie 设置 HttpOnly、SameSite=Lax；生产部署说明要求局域网内仍优先通过反向代理启用 HTTPS。
- 所有改变状态的请求进行 CSRF 防护，并校验同源请求。
- `APP_SECRET_KEY` 由部署者通过环境变量或 Docker Secret 提供，用于派生 Session/Cookie 加密密钥；默认示例值不得用于实际启动。
- Kmoe Session/Cookie 使用认证加密，密文被篡改时拒绝解密。
- Kmoe 密码不写入数据库、配置文件、任务参数、异常详情或日志。
- 日志过滤密码、Cookie、Authorization、CSRF 令牌和带签名下载 URL。
- 下载目标只允许位于配置的下载根目录内。
- API 不提供任意命令执行、任意 URL 下载或任意服务器路径浏览能力。
- Kmoe 会话失效后，暂停需要远端访问的新工作并提示管理员重新登录；系统不保存密码，因此不自动重新登录。

## 11. 错误处理

错误统一映射为结构化类型：

- `auth_expired`：Kmoe Session 失效，需要人工重新登录。
- `quota_exhausted`：账号配额不足，不自动重试。
- `site_changed`：页面或响应结构不再符合解析契约，不更新基线。
- `mirror_unavailable`：所有镜像均不可用，可按退避策略重试。
- `network_error`：连接、超时或临时服务器错误，可重试。
- `disk_full`：磁盘空间不足，停止新下载并提示管理员。
- `file_conflict`：最终路径存在不一致文件，需要人工处理。
- `cancelled`：用户取消，不作为系统错误。

网络类错误最多自动重试全局配置的次数，默认 3 次，采用带抖动的指数退避。认证、配额、磁盘和文件冲突不进行无意义重试。单个任务失败不会中止工作器，批次结果分别统计成功、无新增和失败订阅。

页面显示简洁错误与建议操作；诊断日志使用关联 ID 连接检查批次、订阅和任务，但不得包含敏感信息。

## 12. 可观测性

- 使用结构化日志，字段包含时间、级别、事件类型、关联 ID 和非敏感实体 ID。
- 提供 `/health/live` 存活检查和 `/health/ready` 就绪检查。
- 就绪检查验证数据库可访问、迁移完成和下载根目录可写，不因 Kmoe 暂时不可用而让容器反复重启。
- 仪表盘活动事件与详细日志分离，避免向普通页面暴露内部异常堆栈。
- 日志写到标准输出，由 Docker 管理轮转；首版不内建指标系统。

## 13. 测试策略

### 13.1 单元测试

覆盖内容类型筛选、首次订阅策略、远端快照差异、任务唯一性、状态转换、重试判断、文件名清理和路径边界。

### 13.2 解析契约测试

保存去敏后的 Kmoe HTML 与 JSON Fixture，覆盖登录成功/失败、搜索、漫画详情、三种内容类型、空内容、配额错误和异常页面。解析器面对未知结构必须明确失败。

### 13.3 适配层集成测试

使用本地伪 Kmoe HTTP 服务验证 Cookie、镜像切换、超时、限流、签名地址、Range 支持与不支持、内容长度异常和重试。

### 13.4 API 与数据库测试

使用临时 SQLite 数据库执行真实迁移，覆盖管理员初始化竞争、订阅事务、调度去重、任务领取、取消、恢复和敏感字段不出现在响应中。

### 13.5 浏览器端测试

Playwright 覆盖管理员登录、Kmoe 登录、搜索、创建两种初始化策略的订阅、查看进度、取消与重试失败任务，以及手机尺寸下的主要操作。

### 13.6 Docker 冒烟测试

验证首次启动、健康检查、数据库迁移、两个持久卷、容器重建后的状态保留，以及没有安全密钥时拒绝以不安全默认值启动。

## 14. 部署设计

Docker Compose 默认包含一个应用服务：

- 映射一个局域网访问端口。
- 挂载 `/data` 与 `/downloads`。
- 设置时区。
- 通过 `.env` 或 Docker Secret 提供 `APP_SECRET_KEY`。
- 配置健康检查和合理的停止宽限时间，使运行任务能保存状态。

应用启动顺序为：校验配置、打开数据库、执行迁移、验证目录、恢复任务、启动工作器与调度器、进入就绪状态。优雅停机时先停止领取新任务，再标记或保存运行任务的可恢复状态。

## 15. 数据迁移与备份

所有数据库变更通过 Alembic 管理。执行可能破坏兼容性的迁移前，在 `/data/backups/` 创建带时间戳的 SQLite 备份。备份失败时中止迁移。首版文档提供停止容器后复制 `/data` 和 `/downloads` 的备份与恢复步骤。

## 16. 开发阶段划分

1. 项目骨架、配置、数据库迁移、管理员认证与 Docker 基础。
2. Kmoe 适配层：登录、搜索、详情和 Fixture 契约测试。
3. 订阅领域模型、初始化策略、差异识别与调度。
4. 下载工作器、进度、重试、取消、文件布局和重启恢复。
5. React 管理界面与 SSE。
6. 安全加固、端到端测试、部署与运维文档。

各阶段必须保持可测试边界，不把站点解析、业务规则、HTTP 路由和文件写入集中在同一模块。

## 17. 已知风险与应对

- Kmoe 页面或下载协议变化：通过适配层和去敏 Fixture 隔离并快速发现。
- 镜像内容暂时不一致：按稳定 ID 比较，故障切换后仍需完整响应校验。
- 普通账号不支持 Range：运行时检测能力，不假定所有下载均可续传。
- 短期签名地址过期：每次任务尝试重新获取地址，不持久化后长期复用。
- SQLite 写竞争：单应用进程、短事务、WAL 和有限工作器并发；避免在数据库事务内执行网络或文件传输。
- 磁盘耗尽：下载前检查可用空间，写入失败立即停止任务并保留可诊断状态。
- 账号配额限制：明确展示配额错误，首版不通过多账号规避限制。

## 18. 验收场景

1. 新安装后创建管理员并成功登录 Kmoe，重启容器后 Session 仍有效。
2. 搜索漫画并选择“仅追新”，系统保存当前基线且不下载旧内容。
3. 搜索另一漫画并选择“补齐已有内容”，系统仅为选定类型创建任务。
4. 远端新增一个符合类型的卷后，下次检查恰好创建一个任务；重复检查不创建副本。
5. 远端返回异常空页面时，订阅基线不被清空并显示站点解析错误。
6. 下载中断后，在支持 Range 时续传；不支持时安全重新下载。
7. 下载完成前数据库不显示完成，最终目录不出现伪完整文件。
8. 容器在下载中被重启，启动后任务恢复且不会重复生成最终文件。
9. Kmoe Session 失效后远端任务暂停，管理员重新登录后可继续。
10. 管理员密码、Kmoe 密码、Cookie 和签名下载地址不会出现在数据库明文字段、API 响应或日志中。
